BA Requirement Review: how it works

This project turns a Confluence requirement page into three things: a clear summary for the build team, a short list of questions for the requirement owners, and a finished BRD in PDF and Word. A small team of AI helpers ("agents") does the reading and writing. This guide explains each step in plain words.

The big picture

Five steps, from the Confluence page to the finished BRD. Step 4 is done by you, by hand, with Rovo.

1

Copy the requirements from Confluence

The Team Stores pages are copied from Confluence to your computer as plain text files. Next time, only the pages that changed are copied again.

You type: /confluence-syncYou get: one file per Confluence page
2

Review one requirement page

Two agents read the page together. One writes a plain-language summary of what must be built. The other collects everything that is unclear, missing or contradicting other pages, and turns it into a numbered question list (Q-1, Q-2 …).

You type: /req-team <page>You get: Implementation Summary + Clarification Questions
3

Check the questions against the prototype

A third agent looks at the clickable prototype (the sample app) to see whether it already answers each question. It also lists screens the requirement needs that the prototype doesn't have yet ("hidden build work"). This runs automatically as part of step 2.

Runs inside: /req-teamOr on its own: /prototype-answerYou get: Prototype Answers
4

Double-check the questions with Rovo You, by hand

Before the questions go to the owners, you open the Confluence page and ask Rovo (Atlassian's AI) whether each question is really true: does the page actually say what the question quotes, and is it really missing or contradicting? Questions Rovo can't confirm are fixed or removed.

Where: Rovo, on the Confluence pageHow to do the check →
5

Build the BRD

The summary is laid out in the team's BRD format (the "REQUIREMENTS DOCUMENT M-n.0" layout) and saved as PDF and Word. Questions that are already answered are left out, so the BRD only shows what is still open.

You type: /brd-format <module>You get: BRD as PDF + Word

📝 Summarizer

Reads the requirement page and writes only what the build team needs: scope, who uses it, rules, data, steps, and how to test it. Starts with a glossary. Every rule says which section it came from. Anything unclear goes straight to the Consolidator as an "open item" (OI-1, OI-2 …).

❓ Consolidator

Reads the same page itself and compares it with all the other Confluence pages. Merges duplicates and writes one question list, sorted by importance: P1 blocks the build, P2 should be answered before building, P3 can wait. Each question quotes the source and suggests answers.

🖥️ Prototype answerer

Looks through the clickable prototype to see whether it already answers each question, quoting the exact place in the prototype. It also lists screens and filters the requirement needs that the prototype doesn't have yet.

🔎 You + Rovo Manual check

Not an agent: this is your own double-check. You ask Rovo on the Confluence page whether each generated question is true, so the owners never get a question based on a misread page.

📄 BRD formatter

Lays the content out in the team's BRD format and makes the PDF and Word files. Copies the content word for word and never adds its own opinions. Leaves out questions that are already answered.

🔄 Confluence sync

Not an agent, a command. Copies the Team Stores pages from Confluence and remembers each page's version, so the next run only fetches what changed.

Worked example: Store Home, question Q-13

A real question from the Store Home review on 26 Oct 2026.

The question P2 · Conflict

The "Your close report is ready" card (C-17) should only show if the rep hasn't seen the Close Report yet. But Home is also told never to check whether the report was seen. So when would the card ever appear?

What the prototype does Partial

The card shows on every Closed store, whether or not the report was seen. In practice it works as a permanent link to the report. That matches one of the suggested answers, but the owners still have to confirm it.

What happens next

Because it is only partly answered, Q-13 stays open. Its open item (OI-5) stays in the BRD, and the owners decide: keep the card, or replace it with a plain link.

Rovo double-check You, by hand

Your own check that each generated question is true before it goes to the requirement owners.

AI agents can misread a page. Rovo reads the live Confluence page, so it's a good second opinion. Each question already quotes the exact source text and names the section, which makes checking quick.

1. Pick the questions

Open clarification-questions.pdf. Start with the P1 questions, then P2. Skip the ones the prototype already answered (see prototype-answers.pdf).

2. Open the page in Confluence

Go to the requirement page the question is about, e.g. Store Home (Home Tab), and open Rovo.

3. Ask Rovo

Paste the question and its quoted source text, and ask whether it's true. Use the prompt below.

4. Mark the result

Confirmed: keep it. Not true: remove or fix it. Already answered: note where and don't send it. Then tell Claude which questions to drop, and re-run /brd-format.

Prompt to paste into Rovo

Check whether this question about our requirements is true.

Question: <paste the question text>
It quotes: <paste the "Source / quoted text" column>

1. Does the page really say what is quoted, in that section?
2. Do the two quotes really disagree, or is the detail really missing?
3. Is the answer already written somewhere else in Confluence or Jira?
   If yes, give me the page and the exact sentence.

Answer with one of: Confirmed / Not true / Already answered, then explain.

Example: Q-13

Ask Rovo on the Store Home page: "Store Home section C4 says C-17 shows when 'this user has not seen the report', but Epic B says 'Home reads neither flag'. Is that a real conflict?"

If Rovo says Confirmed: keep Q-13 and send it to the owners.
If Rovo finds an answer: e.g. a newer comment saying C-17 was dropped, note the link and remove Q-13.

Quality checks

Automatic checks stop an agent from finishing until its file is complete.

Summary

Every rule and test has a source reference, and every unclear point has an open-item number.

Questions

Every open item from the summary has a question. No duplicate numbers. Every question quotes its source.

Prototype answers

Every question has an answer row, and every answer points to the exact place in the prototype.

BRD

At least 95% of the source text is in the BRD, tables stay real tables, and the PDF and Word files are up to date.

Glossary

Words you'll see in the outputs.

Agent
An AI helper with one job, e.g. writing the summary.
BRD
Business Requirements Document: the finished document in the team's layout.
Module (M-4.1)
The BRD number for one requirement page, e.g. M-4.1 is Store Home.
FR-4.1.3
A numbered row in the BRD (Functional Requirement).
BR-n / AC-n
A business rule / an acceptance test in the summary.
OI-n (open item)
Something unclear the Summarizer found. Each one becomes a question.
Q-n (question)
A numbered question for the requirement owners.
P1 / P2 / P3
How urgent a question is. P1 blocks the build.
M-n (missing screen)
A screen or filter the requirement needs that the prototype doesn't have.
Prototype
The clickable sample app. It shows how screens behave but has no real database.
Rovo
Atlassian's AI assistant in Confluence and Jira. You use it to double-check that each generated question is true.
Run folder
The folder in output/ holding one review's files, named by date and page.

Tips & FAQ

The UX team changed a Confluence page. What do I do?

Run /confluence-sync, then /req-team on the changed page, then /brd-format. Old outputs are kept as backups.

Why does the BRD have fewer open items than the summary?

Questions the prototype fully answered are left out of the BRD. Partly answered ones stay, listing only the part still open.

Plain language or technical wording?

All agents write in plain language. In /brd-format, choose "Implementation summary" for a plain BRD. "Original spec" copies the Confluence page word for word, which keeps its technical wording.

A review stopped halfway ("spend limit").

Your usage limit was reached. Files already written are kept. When the limit resets, type continue and only the unfinished part is redone.

Some content looks missing compared to Confluence.

A few Confluence widgets (embedded panels, some dates and images) don't come through when pages are copied as text. Agents flag these as gaps instead of guessing.

Can the agents change Confluence or Jira?

No. The Atlassian connection is read-only. Everything is written only to your computer.
